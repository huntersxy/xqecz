本仓库采用**分层、按进程隔离**的配置系统，NestJS API、Go Worker、Vue3 前端各自通过环境变量注入运行时配置，根脚本负责跨进程共享关键变量。

### 1. 使用的框架与工具
- **NestJS API**：使用 `@nestjs/config`（ConfigModule.forRoot）作为全局配置模块，配合 `dotenv` 自动加载 `.env` 文件；TypeORM 连接通过 `ConfigService.get()` 读取 MySQL/Redis 参数。
- **Go Worker**：通过 Node 脚本 `scripts/run-worker.mjs` 启动，该脚本用极简正则解析 `packages/api/.env`，仅提取 `UPLOAD_DIR`、`THUMB_DIR`、`IMAGES_DIR` 三个键注入子进程环境变量，保证 NestJS 与 Worker 指向同一共享上传目录。
- **Vue3 前端**：Vite 构建期通过 `import.meta.env.*` 访问编译时常量（如 `VITE_API_BASE_URL`、`VITE_PROXY_TARGET`、`VITE_BUILD_DATE`），开发服务器通过 `process.env.VITE_PROXY_TARGET` 设置代理目标。

### 2. 核心文件与位置
- `packages/api/src/app.module.ts` — 注册 `ConfigModule.forRoot({ isGlobal: true })`，并通过 `ConfigService` 注入 TypeORM 连接参数。
- `packages/api/src/main.ts` — 直接读取 `process.env.CORS_ORIGINS`、`UPLOAD_DIR`、`PORT` 等环境变量。
- `packages/api/src/redis/redis.service.ts` — 通过 `ConfigService` 读取 `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`、`REDIS_DB`、`REDIS_PREFIX`。
- `packages/api/src/content/content.controller.ts` — 直接使用 `process.env.UPLOAD_DIR` 作为共享卷根。
- `scripts/run-worker.mjs` — 解析 `packages/api/.env` 并过滤出 worker 需要的键，再 `spawn` Go 进程。
- `packages/frontend/vite.config.ts` — 通过 `process.env.VITE_PROXY_TARGET` 控制开发代理，`define` 注入 `VITE_BUILD_DATE`。
- `pnpm-workspace.yaml` — monorepo 工作区定义，允许特定原生依赖的构建。

### 3. 架构与约定
- **配置来源优先级**：进程自身的 `process.env` > 对应包下的 `.env` 文件。Worker 不直接读 `.env`，而是由 Node 脚本从 API 的 `.env` 中抽取必要键后注入。
- **默认值策略**：所有关键配置均提供硬编码默认值（如 `MYSQL_HOST='localhost'`、`REDIS_PORT=6379`、`PORT=3000`、`UPLOAD_DIR='/app/uploads'`），确保本地开发无需额外配置即可运行。
- **跨进程共享约定**：`UPLOAD_DIR`、`THUMB_DIR`、`IMAGES_DIR` 是 API 与 Worker 之间唯一的共享配置契约，由 `run-worker.mjs` 强制同步，避免路径不一致导致文件不可见。
- **前端构建期常量**：Vite 在构建时将 `import.meta.env.*` 替换为字面量，生产环境不会泄露代理配置。

### 4. 约束与规则
- **API 独占数据层**：注释明确「NestJS 独占 DB/Redis，worker 不直连」，Worker 仅做无状态打分，通过 API 间接写入 Redis（如 `writeRecommendList` 原子更新推荐列表）。
- **`.env` 格式约束**：`run-worker.mjs` 使用正则 `/^\s*([A-Z0-9_]+)\s*=\s*(.*?)\s*$/` 解析，要求键名全大写且不含特殊字符，行首可有空格，以 `#` 开头的注释行被忽略。
- **CORS 源配置**：`CORS_ORIGINS` 支持逗号分隔的多域名，默认 `http://localhost:5173`。
- **Redis key 前缀**：通过 `REDIS_PREFIX`（默认 `xqecz:`）统一命名空间，启动时可清理除 session 和 view count 外的全部缓存。
- **端口与服务地址**：API 默认 3000 端口，前端代理默认指向 `http://localhost:3000`，可通过 `VITE_PROXY_TARGET` 覆盖。
