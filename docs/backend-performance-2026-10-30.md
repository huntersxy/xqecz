# 后端热点优化（2026-10-30）

本轮覆盖匿名内容详情、管理仪表盘和 AI 任务图片查询。

## 改动

- 匿名内容详情复用 `cache.GetOrSetJSON`，将同一内容的并发缓存未命中合并为一次加载。内容、点赞数和作者信息由该次加载取得；每个成功的非静默访问仍单独更新 MySQL 浏览量和 Redis 当日计数。
- 已登录用户继续独立查库并校验作者/管理员权限；`silent=1` 继续直接读取当前内容且不增加浏览量。被拒绝的内容和查询错误不会进入公共缓存。点赞数查询失败时返回服务异常，避免缓存不完整的详情。
- 管理仪表盘也复用现有请求合并机制。`fresh=1` 继续直接重算并刷新缓存。
- AI 任务图片的 `archived = false` 条件在 SQL 中执行，避免读取、传输和分配随后会被丢弃的已归档图片。

内容详情缓存仍为 300 秒，仪表盘仍为 60 秒，缓存键和失效入口沿用现有实现。请求合并作用于单个服务进程，没有引入额外服务。

## 可复现的本地测量

基准通过真实 Gin 处理器、临时 SQLite 数据库和 miniredis 发起请求，每轮清空一个详情缓存，然后同时请求同一内容 8 次。为稳定覆盖缓存未命中的重叠窗口，内容读取前在测试回调中加入 10 毫秒延迟。该延迟只存在于测试代码。

```powershell
go -C packages/server test ./internal/modules/content -run '^$' -bench '^BenchmarkDetailColdBurst$' -benchtime=20x -count=1 -benchmem
```

| 指标 | 修改前（65b76dd） | 修改后 |
| --- | ---: | ---: |
| 每轮请求数 | 8 | 8 |
| 每轮内容表读取次数 | 8 | 1 |

20 轮测量中，每轮内容读取减少 87.5%。这反映并发冷缓存场景下的重复查询减少，不代表线上响应时间或吞吐量的提升幅度。

## 验证

- 内容详情测试验证并发读取合并、热缓存命中，以及每次访问的持久化浏览量和当日 Redis 计数。
- 静默读取和作者/管理员/其他用户的审核权限测试验证私有结果不会进入公共缓存。
- 仪表盘测试验证 8 个并发请求只重算一次，以及强制刷新后普通读取使用新缓存。
- AI 任务视图测试同时验证用户和管理员仅取得未归档图片，数据库实际返回行数也只包含这些图片。
- `pnpm server:test`、`pnpm server:vet`、`pnpm build:server` 和 `git diff --check` 通过。

排查期间只读查询了当前配置所连接的 TiDB 的索引和执行计划，没有修改其数据或结构。本轮没有执行线上迁移、部署或生产压测；本地结果不代替上线后的真实流量验证。
